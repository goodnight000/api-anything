    Teach it a site once.

    Give two example inputs. A headless browser loads the page for each. No LLM needed.

    two example inputs
    domain=github.com
    domain=github.io
    headless browser: loading the page…
    the request each load sent
    GET news.ycombinator.com/from?site=github.com
    GET news.ycombinator.com/from?site=github.io
    saved operation: hn-demo links
    GET news.ycombinator.com/from?site={domain}
    Cookie: user=a8f3…c2e1cookie:user
    What changed with the input became the slot {domain}. The rest is a template.
    Cookies and tokens become references. The values stay in ~/.api-anything, never in the spec.

    Then it calls the site like an API.

    Fill the slots and send plain HTTP. JSON comes back, with no browser.

    terminal
    $ api-anything call hacker-news search query=sqlite { "ok": true, "class": "ok", "tier": 1, "data": [{"title": "Hosting SQLite databases on…"}, …], "ms": 111 }
    if the site pushes back, it falls back
    TIER 1
    Node fetch, plain HTTP
    no browser
    TIER 2 · IF THE SITE BLOCKS PLAIN HTTP
    fetch from inside a browser page
    TIER 3 · LAST RESORT, READS ONLY
    run the page, read its own response
    Same agent, same prompt, 1-date flight search: browser 12.9 s · $0.166 → API Anything 8.4 s · $0.074 median of 5 runs

    When the site changes, it repairs the request.

    It re-learns what drifted, and saves the new version only after a replay succeeds.

    1
    It drifts
    The answer stops fitting: a rotated id, a moved field.
    2
    Re-learn
    Rescan the page's scripts, or capture the request again.
    3
    Replay
    Send the new request with the call's own inputs.
    4
    Save
    Only if the replay succeeds. Otherwise, an honest error.
    GET /api/search?q={query} x-build-id: 8f2a1c 93d0e7 the site shipped a new build replay:
    → {"ok": true, "class": "ok", "tier": 1, "healed": true, "data": […]} If the repair fails, the call returns an error, never someone else's data.

    It tells the truth about writes.

    Writes need --allow-writes. Each result says what was sent and whether to send it again.

    terminal
    $ api-anything call my-site postComment text="Ship it" --allow-writes {"ok": true, "class": "ok", "tier": 1, "write": "accepted"} $ api-anything call my-site postComment text="Ship it" --allow-writes {"ok": false, "class": "duplicate", "write": "not_sent", "retry": "no", "nextCall": {"action": "check_site"}}
    the site took it
    same write, so it's refused, not sent twice
    not_sent
    nothing was sent
    not_applied
    the site said it didn't run it
    accepted
    a 2xx: the site took it
    may_have_applied
    it may have run: check before any retry
    applied
    its read-back found it
